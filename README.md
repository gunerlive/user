# ระบบเซ็นเอกสารออนไลน์ (e-Sign)

ระบบสำหรับหนังสือราชการที่ต้องผ่านการลงนามหลายท่านตามลำดับ:
ผู้รับผิดชอบอัปโหลดเอกสาร (PDF) → กำหนดผู้ลงนามและตำแหน่งลายเซ็น → ส่งลิงก์ให้ผู้ลงนามเปิดแล้วเซ็นต่อกันไปทีละคน
(ไม่ต้องล็อกอิน แค่เปิดลิงก์แล้ววาดลายเซ็นด้วยนิ้ว/เมาส์) → เมื่อลงนามครบ ผู้รับผิดชอบตรวจสอบ ดาวน์โหลดไปปริ้นได้
และกดบันทึกเข้าระบบ ซึ่งจะอัปโหลดไฟล์ขึ้น **Google Drive ของโรงเรียนผ่าน Google_API กลาง** แล้วลบไฟล์ชั่วคราวออกจากเซิร์ฟเวอร์ทันที
(ระบบนี้ไม่เก็บไฟล์ถาวรไว้บนโฮสต์)

ระบบนี้**ไม่ทำ OAuth เอง และไม่สร้าง OAuth Client ID ใหม่** — ส่งไฟล์ไปที่ API กลางของโรงเรียนที่
`https://rpk24.ac.th/Google_API/api_upload.php` เท่านั้น ตามข้อกำหนดที่แนบมา

## คุณสมบัติหลัก

- อัปโหลดเอกสาร PDF พร้อมกำหนดรายชื่อผู้ลงนามตามลำดับ
- คลิกบนตัวอย่างเอกสารเพื่อกำหนดตำแหน่งที่จะแสดงลายเซ็นของแต่ละคน (ใช้ pdf.js แสดงผล)
- ผู้ลงนามเปิดลิงก์ส่วนตัวแล้ววาดลายเซ็นด้วยนิ้ว/เมาส์ได้ทันที ไม่ต้องสมัครสมาชิกหรือล็อกอิน
- ระบบบังคับลำดับการเซ็น (คนถัดไปจะเซ็นไม่ได้จนกว่าคนก่อนหน้าจะเซ็นเสร็จ)
- ลายเซ็นถูกวางลงบน PDF จริงทันทีที่เซ็น (ใช้ FPDI ประกอบภาพลงบนเอกสารเดิม ไม่แก้ไขเนื้อหาอื่น)
- แดชบอร์ดติดตามสถานะ: ร่าง / กำลังลงนาม / รอตรวจสอบ / บันทึกแล้ว
- ตรวจสอบ ดาวน์โหลด PDF เพื่อปริ้น และบันทึกเข้า Google Drive ผ่าน Google_API กลางของโรงเรียน
- ไฟล์เอกสารจะถูกลบออกจากเซิร์ฟเวอร์ทันทีหลังบันทึกขึ้น Google Drive สำเร็จ

## โครงสร้างโปรเจกต์

```
config/     ตั้งค่าฐานข้อมูล + การเชื่อมต่อ Google_API กลาง (ห้าม commit config.php)
database/   ไฟล์ schema.sql สำหรับสร้างตาราง
src/        คลาส PHP หลัก (เชื่อมฐานข้อมูล, ตรวจสอบสิทธิ์, ประทับลายเซ็นบน PDF, เรียก Google_API)
public/     เว็บเพจทั้งหมด (แนะนำให้ตั้ง Document Root ของโฮสต์มาที่โฟลเดอร์นี้)
storage/    ไฟล์ PDF ที่กำลังอยู่ระหว่างขั้นตอนเซ็น (ชั่วคราวเท่านั้น — จะถูกลบหลังบันทึกเข้า Drive)
```

## ติดตั้ง

### 1. ติดตั้งไลบรารีผ่าน Composer

```bash
composer install
```

จะได้ไลบรารี `setasign/fpdi` + `setasign/fpdf` สำหรับวางลายเซ็นลงบน PDF เดิม

### 2. สร้างฐานข้อมูล

สร้างฐานข้อมูล MySQL/MariaDB ว่างเปล่า 1 ฐาน แล้วนำเข้าโครงสร้างตาราง:

```bash
mysql -u ชื่อผู้ใช้ -p ชื่อฐานข้อมูล < database/schema.sql
```

### 3. ตั้งค่าระบบ

คัดลอกไฟล์ตั้งค่าตัวอย่าง แล้วแก้ไขให้ตรงกับระบบจริง:

```bash
cp config/config.sample.php config/config.php
```

แก้ไขค่าในไฟล์ `config/config.php`:

- `db` — ข้อมูลเชื่อมต่อฐานข้อมูล MySQL/MariaDB
- `app_base_url` — URL เต็มของระบบนี้ (ไม่มี `/` ปิดท้าย) ใช้สร้างลิงก์เซ็นเอกสารให้ผู้ลงนาม
- `google_api.system_key` และ `google_api.api_secret` — ขอจากผู้ดูแล Google_API กลางของโรงเรียน
  (ดูรายละเอียดการเชื่อมต่อได้ที่ `docs/google_api_reference/`)
- `app_secret` — สุ่มค่าใหม่ด้วยคำสั่ง `php -r "echo bin2hex(random_bytes(32));"`

### 4. ฟอนต์ไทยสำหรับพิมพ์ชื่อกำกับใต้ลายเซ็น (แนะนำ ไม่จำเป็น)

เอกสารราชการไทยกำหนดให้ใช้ฟอนต์ **TH Sarabun New** เป็นมาตรฐาน ดาวน์โหลดไฟล์ `.ttf` แล้ววางไว้ที่
`src/fonts/THSarabunNew.ttf` (path ตามที่ตั้งไว้ใน `config.php` คีย์ `thai_font_path`)

> ถ้าไม่มีไฟล์ฟอนต์ ระบบยังใช้งานได้ตามปกติ เพียงแต่จะไม่พิมพ์ชื่อ-วันที่กำกับใต้รูปลายเซ็นที่วาด
> (จะเห็นแค่ลายเซ็นที่วาดเท่านั้น)

### 5. ตั้งค่าโฮสต์ (Document Root)

**แนะนำ:** ตั้งค่าโดเมน/โฮสต์ให้ Document Root ชี้ไปที่โฟลเดอร์ `public/` โดยตรง เพื่อให้โฟลเดอร์
`config/`, `src/`, `database/`, `storage/` อยู่นอก webroot และปลอดภัยที่สุด

**ถ้าโฮสต์ไม่รองรับการเปลี่ยน Document Root** (เช่นอัปโหลดทั้งโปรเจกต์ไปที่ `public_html` ตรงๆ):
ทุกโฟลเดอร์ที่ไม่ควรเข้าถึงผ่านเว็บ (`config/`, `src/`, `database/`, `storage/`) มีไฟล์ `.htaccess`
ที่ปิดกั้นการเข้าถึงผ่าน HTTP ไว้ให้แล้ว (ใช้ได้กับ Apache) และไฟล์ `index.php` ที่ root จะ redirect
ไปหน้า `public/index.php` ให้อัตโนมัติ

ตรวจสอบว่าโฟลเดอร์ `storage/working/`, `storage/signatures/`, `storage/tmp/` เขียนไฟล์ได้ (permission 755/775)

### 6. เริ่มใช้งาน

เปิดเว็บไซต์ครั้งแรก ระบบจะพาไปหน้า **ตั้งค่าเริ่มต้นระบบ** (`public/setup.php`) เพื่อสร้างบัญชี
เจ้าหน้าที่ผู้รับผิดชอบเอกสารคนแรกด้วยตัวเอง (หน้านี้จะใช้ได้เฉพาะตอนที่ยังไม่มีผู้ใช้ในระบบเท่านั้น)

## วิธีใช้งาน

1. เจ้าหน้าที่เข้าสู่ระบบ → **ออกหนังสือใหม่** → กรอกเลขที่/เรื่อง → อัปโหลดไฟล์ PDF → เพิ่มรายชื่อผู้ลงนามตามลำดับ
2. ระบบพาไปหน้า **กำหนดตำแหน่งลายเซ็น** → คลิกชื่อผู้ลงนามที่ต้องการ แล้วคลิกบนตัวอย่างเอกสารเพื่อวางตำแหน่ง
   ของแต่ละคน → กด **เสร็จสิ้น สร้างลิงก์ให้ผู้ลงนาม**
3. คัดลอกลิงก์ของผู้ลงนามคนแรก ส่งให้ทาง LINE/อีเมล ฯลฯ ด้วยตนเอง
4. ผู้ลงนามเปิดลิงก์ → ดูเอกสาร → วาดลายเซ็น → กด **ยืนยันการเซ็นเอกสาร** → ระบบจะโชว์ลิงก์ของ
   ผู้ลงนามคนถัดไปให้คัดลอกส่งต่อเอง (ทำซ้ำจนครบทุกคน)
5. เมื่อลงนามครบ เจ้าหน้าที่เปิดหน้ารายละเอียดเอกสาร → ตรวจสอบ/ดาวน์โหลด PDF เพื่อปริ้น → กด
   **บันทึกเข้าระบบ (Google Drive)**
6. ระบบอัปโหลดไฟล์ขึ้น Google Drive ผ่าน Google_API กลาง บันทึก `file_id`, `webViewLink`, `name`,
   `mimeType`, `size` ลงฐานข้อมูล แล้ว**ลบไฟล์ชั่วคราวออกจากเซิร์ฟเวอร์ทันที**

## ความปลอดภัย

- ลิงก์เซ็นเอกสารใช้ token สุ่ม 48 ตัวอักษร (192 บิต) ต่อผู้ลงนามแต่ละคน คาดเดาไม่ได้
- ระบบตรวจสอบลำดับผู้ลงนามทุกครั้งก่อนบันทึกลายเซ็น (เซ็นก่อนคิวไม่ได้แม้เปิดลิงก์ล่วงหน้า)
- ทุกฟอร์มมีการป้องกัน CSRF
- รหัสผ่านผู้ใช้เข้ารหัสด้วย `password_hash()` (bcrypt)
- ไฟล์เอกสารอยู่บนเซิร์ฟเวอร์เฉพาะระหว่างขั้นตอนลงนามเท่านั้น ถูกลบทันทีหลังบันทึกขึ้น Google Drive

## ข้อกำหนดของระบบ

- PHP 8.1 หรือสูงกว่า พร้อมส่วนขยาย: `pdo_mysql`, `gd`, `curl`, `json`
- MySQL หรือ MariaDB
- Composer (ใช้ตอนติดตั้งครั้งเดียว ไม่ต้องมีบนโฮสต์จริงถ้า upload โฟลเดอร์ `vendor/` ไปด้วย)
